# Ch 9 — Four Questions Is Not a Test

**Location:** `book1_chapter_9_four_questions_is_not_a_test.md`

## Concepts
- **Selection bias in developer-written tests** (lines 25–37): "A test set written by the developer is not a test set. It is a demonstration." The developer unconsciously avoids the queries that would expose weaknesses. REQ-T acceptance criterion: test-set authorship/review should not be solely the implementer (process note, not automatable — flagged as a limitation in the final report for this solo-session build).
- **Why single-number accuracy fails** (lines 39–53): can't distinguish retrieval failure vs prompt failure vs chunking failure → "Accuracy without dimension is undebuggable."
- **C-022 RAGAS metrics** (lines 55–71): four dimensions exist — Faithfulness, Context Precision, Answer Relevance, Context Recall. Book 1 explicitly uses only **Faithfulness** (grounded-in-context ratio) and **Context Precision** (retrieved-chunk relevance ratio) because the other two require ground-truth labels the Book 1 test set doesn't yet have. **Book 2 scope, not this build**: Answer Relevance, Context Recall.
- **C-023 Test-set discipline**: write before seeing scores; include queries engineered to require the fallback (empty `relevant_chunk_ids`) as a deliberate edge case (code lines 81–185, 20 cases).
- **Evaluation harness** (`evaluation/evaluate.py`, lines 191–231): builds a `datasets.Dataset` with `{question, answer, contexts, ground_truth}` per case, calls `ragas.evaluate(dataset, metrics=[faithfulness, context_precision])`.
- **Book 1's own baseline (their 5-product catalog, OpenAI path): Faithfulness 0.71, Context Precision 0.82** (lines 233–240). These numbers are **the book's own measured results, not a target this build must hit** — this build has a different (50-product) catalog and, per ADR-001, a different (Ollama) default model, so its own baseline will differ and must be measured independently, not copied from the book.
