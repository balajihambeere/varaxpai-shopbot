# Ch 6 — The Right Answer Is Already There

**Location:** `book1_chapter_6_the_right_answer_is_already_there.md`

## Concepts
- **The "always returns something" failure** (lines 11–35): a winter-wedding query returns the anarkali suit at 0.51 similarity; the model answers from it confidently anyway. Named as "Confident Drift resumed... from a retrieved document that scored 0.51," i.e. C-001 recurring at the retrieval layer, not the model layer.
- **The opposite failure — threshold too high** (lines 37–53): threshold 0.90 discards two genuinely correct answers (0.87, 0.84) for a summer-wedding query. "The threshold he set was calibrated for certainty rather than relevance."
- **C-013 Threshold calibration methodology** (lines 55–65): test N queries against the real catalog, record top-result scores, find the natural gap between correct-result scores and incorrect-result scores. For the 5-product catalog: correct ∈ [0.78, 0.94], incorrect ∈ [0.48, 0.68], gap at 0.68–0.78 → **threshold = 0.75**. Explicitly stated to need recalibration as the catalog grows (book flags this as Book 2 work via RAGAS-driven calibration) — for a 50-product catalog (this build's actual data), **ENGINEERING-DECISION required**: recalibrate 0.75 empirically rather than assume it transfers (see requirements REQ-N and ADR).
- **C-012 Retriever as abstraction**: single `retrieve(query, chunk_type=None, product_id=None) -> list[dict] | None` function hides the vector-store choice so a future swap (ChromaDB → Qdrant) doesn't ripple through call sites (lines 67–80, code lines 83–176).
- **Fallback contract**: `retrieve()` returns `None` when nothing clears threshold; caller must render the support-contact fallback, never an empty/guessed answer.
- **Competing-chunk problem**: near-identical policy chunks across products (e.g. two 7-day return policies) can both clear threshold; fix is metadata `where` filtering *before* similarity runs, not after (lines 199–229). Framed explicitly as preventing a *future* problem (at 5 products the model "gets away with it" due to query wording; "it is preventing a future one" per Krishna, line 245) — directly relevant since this build's real catalog has 50 products, where the problem is no longer hypothetical.
- **k (MAX_RESULTS) = 3 default** (lines 249–257): rationale — k=1 is fragile to a single wrong retrieval, k=10 dilutes attention and raises cost; 3 lets the model triangulate. Specific retrievers (care-only, policy-only) may use k=1 or k=2.
- **Separation of concerns stated explicitly** (lines 259–267): retriever finds evidence; it does not decide the answer. Failures are diagnosed by layer: wrong chunk retrieved → retrieval bug (embeddings/chunking/threshold/filter); right chunk, wrong answer → prompt/model bug. This is the debugging methodology the test suite (REQ-T) and traceability table should preserve.

## Why it matters
"The retriever is the gatekeeper of the Grounding Layer... Get this decision right and Confident Drift has nowhere to enter." This is the single component most directly responsible for REQ-N "no answer without adequate evidence."
