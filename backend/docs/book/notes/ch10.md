## Concepts
- **Validation of the whole premise** (lines 17–34): the exact question-shape that caused the original 31-ticket failure (Ch 1, cotton-lining question) recurs from a real beta user (Meera) and is now correctly deflected to support instead of answered with an invented detail. This is the book's own acceptance test for the entire book's thesis.
- **C-024 Vocabulary-gap fix** (lines 39–64): Indian-English "function" (= social event) isn't in the catalog's occasion vocabulary; query misroutes to casual wear at 0.71. Fix: add "function" as an occasion synonym to festive-product metadata and re-ingest — a **data fix, not a model/retriever fix**. Directly reusable for this build's real 50-product catalog (already pre-applied per the comment header in `data/products.py`: "Ch. 10 fix applied").
- **C-025 Multi-intent query limitation** (lines 66–74): a single embedding vector cannot represent "festive AND warm" well; book's Book-1-scope fix is to answer with the best single-vector result plus an explicit caveat in the answer text, rather than attempt multi-query retrieval (which is deferred to Book 2). **This is an accepted, documented limitation, not a bug to "fix" in this build** — must be reflected in requirements as a known limitation (REQ-F, priority COULD, not MUST) and in the final report's "book concepts not implemented."
- **C-026 Threshold-adjacent type-mismatch fix** (lines 76–99): a chunk can score just above threshold (0.77) while answering the wrong question *type* (saree chunk retrieved for a jewellery question zUdyog doesn't sell). Fix is a **one-line prompt addition**: if retrieved context describes a product but doesn't address the question type asked, say so and route to support — not a systematic fix (book defers a "corrective retrieval step" to Book 3).
- **Final architecture recap** (lines 125–145): FastAPI → retriever (embed query → ChromaDB nearest-neighbor, threshold-filtered) → prompt (constrained, temp=0, GPT-4o-mini in the book's path) → JSON response. Confirms no component changed between chapters; each chapter added one layer.
- **Cost evidence**: total OpenAI spend for the entire Book 1 build = ₹7.60 (line 109) — useful as a sanity check for the cost assumption in this build's non-functional targets, though this build defaults to the free Ollama path (ADR-001) so the actual cost target is ₹0 unless the user later supplies an OpenAI key.

## Why it matters
