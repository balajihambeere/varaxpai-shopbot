# Ch 8 — Give It a Door

**Location:** `book1_chapter_8_give_it_a_door.md`

## Concepts
- **Why not Flask** (lines 27–33): synchronous by default — blocks the whole server for ~200–400ms per external API call (embedding + vector search + LLM call, sequenced); no native Pydantic validation or auto-docs.
- **Why not ngrok as a permanent answer** (lines 35–41): no persistent URL, no process management, no error handling/logging; it is a **development bridge only**, explicitly re-used later in the same chapter for exactly that purpose.
- **C-018 FastAPI chosen**: async by default (concurrent requests don't block on external calls), auto-generates OpenAPI/Swagger docs at `/docs`, Pydantic request/response validation (lines 43–53).
- **C-019 Input validation — three failure modes anticipated and closed** (lines 55–65, code lines 100–133): empty questions, excessively long questions (>500 chars), prompt-injection-shaped input (regex patterns for "ignore previous instructions," "you are now," "act as," "system prompt," "forget everything"). Also smart-quote/zero-width-character normalization (invisible characters that break downstream matching).
- **C-020 Lifespan pattern** (lines 166–177): build the LangChain chain once at server startup (`@asynccontextmanager` + FastAPI `lifespan=`), never inside a request handler — "Build once. Serve many. Never build inside request handlers." Avoids 2–3s of redundant setup per concurrent request.
- **Endpoints** (code lines 69–160): `GET /health` (required for deployment platform health checks), `POST /ask` (`QuestionRequest{question, session_id="default"}` → `AnswerResponse{answer, session_id}`).
- **C-021 Deployment ladder** (lines 211–335): localhost → ngrok (temporary public tunnel for remote beta testers / investor demo) → Railway (`Procfile`: `web: uvicorn src.api:app --host 0.0.0.0 --port $PORT`, env vars moved to dashboard, persistent public URL). Explicit principle: "Development tools exist to delay infrastructure decisions until the developer understands what is being deployed... Using prototype tools in production creates fragility that fails at the worst moment."
- **Confirms architecture invariant**: "The API changed nothing about what ShopBot knows... The door is new. What is behind it is not." — i.e. the API layer MUST NOT alter retrieval/threshold/prompt behavior; it only exposes it.
