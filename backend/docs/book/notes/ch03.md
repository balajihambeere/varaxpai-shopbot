# Ch 3 — What 1536 Numbers Actually Mean

**Location:** `book1_chapter_3_what_1536_numbers_actually_mean.md`

## Concepts
- **Keyword search failure** (lines 1–46): demonstrated with 4/6 real queries returning zero results because customer vocabulary ≠ catalog vocabulary ("light fabric" vs "breathable"). Rules out keyword search as the retrieval mechanism — **BOOK-SPECIFIED constraint**: do not build ShopBot's retrieval on keyword/full-text search.
- **Rejected alternatives** — synonym dictionaries (incomplete, unmaintainable for Indian-fashion vocabulary) and structured filters (can't parse free text) (lines 51–72). Filters are kept as a *complement* (ChromaDB metadata `where`), not a replacement.
- **C-005 Embedding**: text → 1536-dim (OpenAI `text-embedding-3-small`) coordinate; semantic distance ≈ geometric distance (lines 75–91).
- **C-006 Cosine similarity**: `(A·B)/(|A||B|)`, range −1..1; practical bands: >0.9 near-paraphrase, 0.7–0.9 related, 0.5–0.7 loosely related, <0.5 unrelated (lines 201–221). This scoring function is reused unchanged through Ch 4, 6, 9, 10.
- Worked demo (`src/embed_demo.py`, lines 97–167) proves 5/5 test queries rank the correct product first with no shared vocabulary — this is the acceptance evidence pattern REQ-F test cases should follow.
- Cost data (lines 259–267): ingesting 5 products ≈ ₹3–4; per-query embed ≈ ₹0.002. Carried into non-functional cost targets.

## Why it matters
C-006's score becomes "load-bearing in Chapter 6" (explicit book statement, line 219) for the retrieve-or-withhold decision — this is the single most important number in the whole pipeline (REQ-N-00x, retrieval threshold).
