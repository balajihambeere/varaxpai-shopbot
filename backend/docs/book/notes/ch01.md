# Ch 1 — The Problem With Brilliant Liars

**Location:** `book1_chapter_1_problem_with_brilliant_liars.md`

## Key concepts

### C-001 Confident Drift
- **What the book says:** An LLM that lacks business-specific facts answers from learned statistical patterns ("what answers sound like") instead of from verified fact, with no change in tone or confidence. (lines 37–75)
- **Why it exists (named):** It is the invisible-failure-mode that makes AI-assistant mistakes expensive and hard to catch — HTTP 200, fluent prose, wrong content.
- **How it works:** The model predicts plausible continuations of text; when the specific fact was never in training data, it still produces a plausible-sounding, unhedged answer.
- **Where used:** Diagnostic vocabulary for every later failure in the book (Ch 6's 0.51-score retrieval, Ch 7's unconstrained-prompt drift, Ch 9's Faithfulness gap).
- **How it becomes part of the app:** Drives every anti-drift design choice — the whole point of the Grounding Layer is to prevent C-001.

### C-002 Grounding Layer
- **What the book says:** "A design decision: between every question and every answer, there must be a step that retrieves current, specific, relevant evidence from your actual data." (preface, lines 93–97; Ch1 lines 153–163)
- **Why it exists:** Moves the "point where the system decides what is true" from inside model weights to an explicit retrieval step.
- **How it works:** Retrieve → place evidence in front of the model → model reads and answers only from it.
- **Where used:** The architecture spans Ch 3–8 (embeddings, ChromaDB, chunking, retriever, prompt, API).
- **How it becomes part of the app:** This *is* the system being built — REQ-F-001 through the retrieval+prompt pipeline.

### C-003 Pramana Framework
- **What the book says:** Named after the Sanskrit term for a valid source of knowledge (Nyaya school); "the Grounding Layer is, in precise philosophical terms, the Pramana of a RAG system." (preface, lines 121–131)
- **Why it exists:** Gives the book's architecture and diagnostic vocabulary a name.
- **How it becomes part of the app:** Terminology only — no code artifact. Used in later chapters as "Pramana contract," etc.

## Three failed fixes (BOOK-SPECIFIED, documented so they are NOT repeated)
1. Stricter/hedging prompt alone → reduces expressed confidence, not wrongness (lines 83–91).
2. Paste entire catalog into every prompt → 20x cost increase, inconsistent attention across long context (lines 93–101).
3. Fine-tune on catalog data → knowledge frozen at training time, doesn't update with catalog changes (lines 103–113).

**ENGINEERING-DECISION carried forward:** None of these three approaches should be implemented as alternatives; the book explicitly rules them out and the production app follows that ruling (REQ-N, "no full-catalog-in-prompt", "no fine-tuning").
