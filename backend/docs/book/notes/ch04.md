# Ch 4 — The Memory That Thinks

**Location:** `book1_chapter_4_the_memory_that_thinks.md`

## Concepts
- **Why a Python loop / regular DB fails at scale** (lines 9–53): O(n) cosine-similarity loop costs ~80ms/1k products, ~800ms/10k, ~8s/100k — unacceptable for live queries. Regular (relational) DBs lack ANN index structures; `pgvector` exists but a naive setup still degrades toward full scan.
- **ANN (Approximate Nearest Neighbour) search** (lines 47–53): trades a small accuracy loss (~99.5% exact-match rate) for millisecond-scale search at large N.
- **Alternatives considered and rejected for this stage**: FAISS (index, not a database — no persistence/concurrency story) and managed cloud vector DBs (Pinecone/Weaviate/Qdrant — paid, premature before the architecture is proven) (lines 55–63).
- **C-007/C-008 ChromaDB**: `PersistentClient(path="./chroma_db")`, HNSW index, `hnsw:space: "cosine"` (must be set explicitly — default is L2/Euclidean, which "does not behave as well for text embeddings," line 100). **BOOK-SPECIFIED** vector store for Book 1; book explicitly states Book 2 migrates to Qdrant Cloud — **out of scope for this build** (tag `UNKNOWN / NOT SPECIFIED IN BOOK` for anything beyond Book 1's ChromaDB approach).
- **Ingestion** (`src/ingest.py`, lines 119–195): one `embed_documents()` call for all texts, then `collection.add(ids, embeddings, documents, metadatas)`.
- **C-009 Metadata**: stored per-chunk for (a) pre-filtering via `where={...}` before similarity runs, and (b) carrying display data (category, price) to the response layer (lines 295–313).
- **Cost data**: 5 products ≈ ₹0.10; 500 ≈ ₹10; 5,000 ≈ ₹100, one-time; per-query ≈ ₹0.002 (lines 314–321).

## Why it matters
"What is not in ChromaDB cannot be retrieved. What cannot be retrieved cannot be cited. What cannot be cited cannot be answered." (line 332) — this sentence is the direct basis for REQ-N "no answer without a stored, retrievable source."
