# Ch 5 — Cut It Right

**Location:** `book1_chapter_5_cut_it_right.md`

## Concepts
- **The "blob problem"** (lines 29–45): one embedding per product (8 topics in 241 words) dilutes the vector toward the average of all topics; a 4-word care instruction barely moves it. Diagnosed via a real failure: Meera's dry-cleaning query retrieved the wrong product (saree ranked 3rd, cotton kurta 1st).
- **The opposite failure — over-splitting** (lines 47–59): sentence-level chunks lose anchoring context ("Dry clean only" with no product name attached is nearly unsearchable).
- **Rejected alternatives**: (1) rewrite descriptions to favor one query type — helps one query type, hurts others; (2) store 5 differently-emphasized copies per product — works but creates an update/maintenance nightmare and contradictory-chunk retrieval as phrasings drift (lines 61–81).
- **C-010/C-011 Chunk-by-concern**: one product → up to 5 chunk types — `identity`, `variants`, `policy`, `care`, one `faq` chunk per FAQ entry (lines 83–196, `product_to_chunks()`). Query-type distribution that motivates this split (from real support tickets): 43% variants/availability, 28% identity/occasion, 17% policy, 12% FAQ (lines 93–103).
- **Anchoring rule**: every chunk text begins with the product name so it is meaningful retrieved in isolation.
- **"One chunk. One question. One clear answer."** (line 423) — the book's single governing rule for all future chunking decisions.
- **Common chunking mistakes enumerated** (lines 429–441): too small, too large (>300–400 words), splitting mid-sentence, no metadata, identical boilerplate chunks across products — each is a **negative test case** the test suite should include (REQ-T, mutation/fault check §8/§11).
- **Index rebuild requirement**: changing the chunking strategy invalidates the existing ChromaDB collection — must `rm -rf chroma_db/` and re-ingest (lines 302–352). This is an operational runbook item (docs/operations).

## Why it matters
This chapter is explicitly called "the most consequential chapter in the book that does not involve a language model" (closing line) — chunk quality bounds retrieval quality, which bounds everything downstream (Faithfulness, Context Precision in Ch 9).
